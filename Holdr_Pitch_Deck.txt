EXECUTIVE SUMMARY:
Holdr is a decentralized, trust-minimized escrow application engineered natively for
the BOT blockchain. Built with pure Solidity (^0.8.24) and OpenZeppelin 5.x security
primitives, Holdr guarantees that neither freelancers nor clients can be trapped,
cheated, or held hostage by centralized platforms.

A buyer creates a milestone deal, locks native BOT into the contract, and names a
trusted third-party arbiter agreed upon with the seller. The seller delivers work,
initiating a verifiable review window. If approved, funds release immediately. If
disputed, the chosen arbiter inspects evidence onchain and allocates funds. Built-in
game-theoretic timeouts (overdue refunds, silent buyer claims, and a 14-day arbiter
fallback split) ensure funds can never be frozen indefinitely.

All deal metadata (titles, descriptions, delivery notes, and dispute claims) is
stored 100% onchain as plain UTF-8 strings. No IPFS, no backend servers, no fees.

SLIDE 2: THE PROBLEM IN FREELANCE PAYMENTS
--------------------------------------------------------------------------------
The global freelance and gig economy processes over $1.5 Trillion annually, yet
relies on extractive, fragile Web2 platforms plagued by structural failures:

1. Extractive Take Rates (10% - 20%):
   - Platforms like Upwork, Fiverr, and Freelancer extract up to 20% from service
     providers, reducing real take-home pay and penalizing repeat business.

2. Unilateral Payment Holds & Chargebacks:
   - Centralized payment rails (PayPal, Stripe) allow arbitrary 180-day fund holds
     and chargeback fraud, leaving contractors unpaid after work has been delivered.

3. Black-Box Dispute Settlement:
   - When conflicts arise, outsourced platform support agents make opaque rulings
     with zero cryptographic auditability, routinely siding with big spenders over
     freelancers.

4. Web3 Escrow Over-Engineering:
   - Existing Web3 escrows depend on offchain oracle networks, complex multi-token
     staking, external IPFS pinning gateways that break, or admin-governed DAO votes
     that take weeks to settle.

SLIDE 3: THE SOLUTION — HOLDR
--------------------------------------------------------------------------------
Holdr introduces a lightweight, permissionless, and immutable escrow primitive:

- 0% Protocol Fees:
  Holdr charges zero protocol tax. 100% of escrowed funds flow directly from buyer
  to seller. No platform rent extraction.

- 100% Fully Onchain Metadata:
  All project specifications, delivery notes, and dispute reasons are stored
  directly in smart contract storage. Zero external cloud or IPFS points of failure.

- Strict Pull-Based Settlement (`pendingBalance` + `withdraw`):
  Funds never leave the contract via push transfers. Instead, state transitions
  credit user balances, which are pulled via `withdraw()`. An uncooperative or
  reverting counterparty can never block or grief any transaction.

- Guaranteed Dual-Sided Timeout Protections:
  * Overdue Delivery Refund: If seller fails to deliver before the deadline,
    the buyer can immediately claim a full refund.
  * Silent Buyer Auto-Claim: If the buyer stays silent after delivery, the seller
    claims the full payment as soon as the review window expires.
  * Inactive Arbiter 50/50 Split: If an arbiter fails to rule within 14 days of a
    dispute, either party can execute an automatic 50/50 settlement.

- No Admin Powers, No Upgradeability:
  No contract owner, no pausable state, no fee switch, and no proxy backdoors.
  Only the designated deal participants and arbiter can ever interact with escrow funds.

Core Protocol Design (`Holdr.sol`):

        [ BUYER ]                                   [ SELLER ]
           |                                            |
    createDeal() {msg.value}                   markDelivered(note)
    deliveryDeadline = now + deliveryDays       reviewEnd = now + reviewDays
           |                                            |
           v                                            v
     +-----------+       Delivered               +-------------+
     |  FUNDED   | ----------------------------> |  DELIVERED  |
     +-----------+                               +-------------+
       |       |                                   |     |     |
       |       | release()                         |     |     | claimAfterReview()
       |       v                                   |     |     v (if review expired)
       |   +-----------+ <-------------------------+     |   +-----------+
       |   | COMPLETED |      release()                  |   | COMPLETED |
       |   +-----------+                                 |   +-----------+
       |                                                 |
       | refundOverdue() (if deadline passed)            | openDispute()
       v                                                 v
     +-----------+                               +-------------+
     | REFUNDED  |                               |  DISPUTED   |
     +-----------+                               +-------------+
                                                   |         |
                          resolve(sellerAmount)    |         | splitAfterArbiterTimeout()
                          (Arbiter only)           |         | (if 14 days passed)
                                                   v         v
                                             +--------------------+
                                             |      RESOLVED      |
                                             +--------------------+

Pull-Payment Payout Vault:

SLIDE 7: GAME-THEORETIC DISPUTE SAFEGUARDS
--------------------------------------------------------------------------------
Holdr balances incentives between all three parties to achieve fair equilibrium:

1. Prevention of Frivolous Disputes:
   - Disputes can only be opened during the active review window (1–14 days) by
     either buyer or seller with a detailed onchain reason (1–500 bytes).

2. Neutral Arbiter Empowerment:
   - The arbiter is selected mutually before funding. The arbiter has fine-grained
     discretion to allocate from 0 to 100% of the deal amount to the seller, with
     the remainder automatically refunding the buyer.

3. Absent Arbiter Defense:
   - If an arbiter fails to respond, neither party is held hostage. After the
     14-day `ARBITER_TIMEOUT`, either party can trigger an automated 50/50 split
     (with any odd wei credited to the buyer).

4. Reentrancy & Denial-of-Service Immunity:
   - Pull-based architecture isolates each user's payout. If a malicious contract
     reverts upon receiving BOT, only its own withdrawal fails; other parties and
     unrelated deals continue processing without interruption.
